# Setup de entorno (resumen)

Este apartado es un **repaso breve** de las alternativas de entorno para trabajar con **Python + notebooks** y **Git/GitHub**.
No incluye el paso a paso completo de instalación: dejamos **enlaces oficiales** y tutoriales para profundizar.

## ¿Qué necesitás para el taller?

- Ejecutar **Python** (scripts y/o notebooks).
- Instalar paquetes (dependencias) y trabajar con un **entorno aislado**.
- [_Para el trabajo final_] Usar **Git** para clonar el repositorio del taller y entregar cambios (push/pull). Esto requiere una cuenta en **GitHub**.

## Elegí una alternativa

- **Si no querés instalar nada local** → **Google Colab**.
- **Si querés entorno local moderno y liviano** → **VS Code + Python + uv**.
- **Si ya usás Conda / ciencia de datos** → **Conda + Jupyter**.

---

# 1) Alternativa: Google Colab (online, sin instalación)

## Qué es
Google Colab es un entorno en la nube para ejecutar **Jupyter Notebooks** desde el navegador.

## Flujo de trabajo
- Abrís un notebook en el navegador.
- Ejecutás celdas y probás código rápidamente.
- Guardás el `.ipynb` (Drive / descarga) y, si corresponde, lo versionás con Git.

## Enlaces oficiales
- Abrir Colab: https://colab.research.google.com/
- Colab (portal): https://colab.google/
- Documentación / notebooks (Google Developers): https://developers.google.com/colab
- Recursos / notebooks (Google Developers): https://developers.google.com/colab/notebooks
- FAQ oficial: https://research.google.com/colaboratory/faq.html

# 2) Alternativa: Entorno local “manual” (VS Code + Python + uv)

## Qué es
Un entorno local de desarrollo con:
- **VS Code** (editor)
- **Python** (intérprete)
- **uv** (gestión de versiones de Python, entornos virtuales y paquetes)

## Flujo de trabajo
- Clonás el repo con Git. (Ver sección Git más abajo si no sabés cómo.)
- Creás un entorno virtual por proyecto (por ejemplo `.venv`).
- Instalás dependencias y ejecutás scripts o notebooks desde VS Code.

## Mínimo necesario
1. Instalar Python.
2. Instalar VS Code.
3. Instalar uv.
4. En el proyecto: crear/activar entorno virtual e instalar dependencias.

## Enlaces oficiales
### Python
- Descargas oficiales: https://www.python.org/downloads/
- Documentación oficial: https://docs.python.org/

### VS Code
- Descargar VS Code: https://code.visualstudio.com/download
- Python en VS Code (docs): https://code.visualstudio.com/docs/languages/python
- Entornos Python en VS Code: https://code.visualstudio.com/docs/python/environments

### uv (Astral)
- Instalación: https://docs.astral.sh/uv/getting-started/installation/
- Instalar y gestionar Python con uv: https://docs.astral.sh/uv/guides/install-python/
- Entornos y paquetes (uv pip / environments): https://docs.astral.sh/uv/pip/environments/

# 3) Alternativa: Conda + Jupyter Notebooks (Anaconda / Miniconda)

## Qué es
Conda es un gestor de **entornos** y **paquetes** muy usado en ciencia de datos.  
Podés instalarlo como:
- **Anaconda Distribution** (más completo, incluye muchas herramientas)
- **Miniconda** (más liviano, base mínima)

## Flujo de trabajo
- Creás un entorno por proyecto (por ejemplo `conda create -n taller python=...`).
- Instalás dependencias.
- Ejecutás notebooks con Jupyter (o desde VS Code usando el kernel del entorno).

## Enlaces oficiales
- Instalar Anaconda Distribution: https://www.anaconda.com/docs/getting-started/anaconda/install
- Instalar Miniconda: https://www.anaconda.com/docs/getting-started/miniconda/install
- Documentación de conda: https://docs.conda.io/
- Gestión de entornos (conda): https://docs.conda.io/docs/user-guide/tasks/manage-environments.html
- Instalar Jupyter: https://jupyter.org/install

# Git (breve): instalación en Windows y Linux

## Requisito: cuenta en GitHub
- Registro: https://github.com/signup

## Instalar Git
- Windows (Git for Windows): https://gitforwindows.org/  
  (alternativa oficial desde git-scm): https://git-scm.com/install/windows
- Linux (git-scm): https://git-scm.com/install/linux

## Configuración mínima (para commits)
- Configurar `user.name` y `user.email` (una vez por máquina).
- Autenticación:
  - HTTPS (simple)
  - SSH (recomendado a mediano plazo):
    - Generar clave SSH: https://docs.github.com/en/authentication/connecting-to-github-with-ssh/generating-a-new-ssh-key-and-adding-it-to-the-ssh-agent
    - Agregar clave a GitHub: https://docs.github.com/en/authentication/connecting-to-github-with-ssh/adding-a-new-ssh-key-to-your-github-account
